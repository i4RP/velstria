ヒーローのパラメータを変更して」）。`MatchConfig.currentSimVersion` 19、`MagicChessConfig.currentSimVersion` 2。

- 正本: `tools/hero_stats_spec.mjs`（値と出典）→ `node tools/hero_stats_apply.mjs` が `master_runtime.json` の heroes を書き換える

  `tools/gen_runtime_data.py` は古いデータを書き出すので使わない。

### 攻撃速度の「+X%」の読み方

用語注釈は「現在の攻撃速度 = 基礎攻撃速度 + 追加攻撃速度 × 攻撃速度比率。毎秒の攻撃回数を決める（毎秒 3 回まで）」、
「追加攻撃速度 = スキル・装備・エンブレムから得る攻撃速度」。装備の「攻撃速度 +30%」は 1.0 回/秒の 30% = **+0.30 回/秒**を
追加攻撃速度として足す、と読んだ（基礎への掛け算ではない。比率 30〜90% のヒーローは追加分だけが縮む、という Fandom・Liquipedia の
説明とも合う）。スキルの「攻撃速度 +35%」（趙子龍の奥義・ミヤのパッシブなど）も同じく +0.35 回/秒の追加。
**確かめ方**: 訓練モードで攻撃速度装備を 1 つ買う前後のステータス画面の攻撃速度（1.06 → 1.36 なら加算）。

### 移動速度の逓減（率は資料に無い）

用語注釈は「230 未満・420 超では加速も減速も逓減する」までで、**率は書いていない**（Fandom の Movement speed・Slow のページも
「unknown rate」）。Velstria は仮に「閾値を越えた分の半分だけ効く」（`Balance.moveSpeedDecayRate = 0.5`）にした。
効果（加速・減速）で動いた分だけを逓減させ、もともと 230 未満の基礎（225 のヒーローなど）はそのまま。ヒーローだけに掛け、
ミニオン・モンスターには掛けない（それらの速さはワールドの単位で、MLBB の値ではないため）。
**確かめ方**: 訓練モードで加速を重ねて 420 を超えたときの表示値と、減速を重ねて 230 を下回ったときの表示値を式の値と比べる。

### 防御の下限（資料の食い違い）

Fandom の用語注釈「Physical Defense」は 1 つの項目の中に「貫通で 0 を下回らない」（古い文）と「−60 を下回らない」（新しい文）の
両方が書いてあり、Fandom の Notes ページは「0 を下回らない」だけ。監査 A（Fandom の Physical penetration・Defense reduction の
ページ）とユーザーの指示に従い **−60** にした（固定貫通・防御低下で防御は負になり、受けるダメージは最大 200%）。
**確かめ方**: 訓練モードで防御の低い相手に固定貫通の装備で当てたダメージの表示を、120/(120 + 負の防御) と比べる。

### 強靭と打ち上げ（資料の食い違い）

- 日本語クライアント: 「受けるコントロール効果の持続時間を短縮するステータス（**制圧および強制ブリンクを除く**）」。
- Fandom の Resilience: 「打ち上げ・ノックバック/引き寄せ・制圧を除く」。

日本語を優先し、**打ち上げ（airborne）は強靭で縮む**ことにした。スキルの説明に「強靭の影響を受けない」とある打ち上げ
（セイバーの奥義）は縮まない（`Kit.knockUp(ignoresResilience: true)`）。汎用のノックバック（押し出し + 着地の 0.25 秒）は強制ブリンクなので
縮まない。キットの引き寄せ・押し出しは状態ではなく強制移動なので、もともと強靭は関係しない。

## 3. 能力値の意味（Velstria の単位）

- 距離・射程・移動速度は MLBB × 100（射程 4.8 → 480、近接 1.8 → 180）。`isRanged` は射程 300 以上（10 体とも分類は変わらない）。
- 移動速度は master に **MLBB の値そのまま**（例 250）を持ち、式の後に `Balance.mapScale`（1.35）を掛けてワールドの単位/秒にする。
  コレクション画面の「移動速度」は MLBB の値（`HeroGrowth.baseStats`）。
- 攻撃速度は Lv1 の値 + 成長 × (Lv − 1)、攻撃速度比率は 1 = 100%（10 体とも 100%）。
- HP 回復・マナ回復は毎秒。マナは Lv1 の最大値 + 成長 × (Lv − 1)。

## 7. テストとバランス

- 式のテストは MLBB の式に書き直した（出典はテストのコメント）: `CombatDamageTests`（防御 120・−60・被ダメ軽減・シールドの順）、
  `CombatStatusTests`（減速の合計・強靭）、`ItemEffectsTests`（強靭の掛け算・攻撃速度の加算）など。
- 汎用スキルとキットのスキルのダメージの式（換算の倍率）は変えていない（次の段階）。能力値だけが MLBB の尺度になったので、
  `KitBalanceTests`（キット対汎用の勝率差）と `SkillBalanceTests`（TTK の帯）の結果が変わった。
- 計測環境: Windows 11・Swift 6.4（Release、`swift test -c release`）。どれも 1v1 のハーネスと AI 対戦の決定論のシミュレーションの値で、
  実機の FPS や操作感ではない。
