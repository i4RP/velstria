# VELSIA ゲーム設計書（実装正本 v1.0）

仕様パッケージ `VELSTRIA_復元版パッケージ/` はコンテンツ名・基礎数値の正本。本書はそこに無い
「ゲームとして動かすための具体ルールと数値」を定義する。数値は `Balance.swift` に集約し、本書と一致させる。
数値はプレイテスト前の初期仮説であり、ヘッドレス AI 対戦シミュレーションで調整する。

## 0. v1.0 スコープ
- オフライン 5v5 対 AI（プレイヤー 1 名 + AI 味方 4 + AI 敵 5）。サーバー不要で完結。
- 全 24 ヒーロー / 96 アクティブスキル + 24 パッシブ / 92 装備（Mobile Legends の図鑑を写したもの） / 15 バトルスペル / 30 ルーン。
- モード: 通常戦(対AI, 難易度 3 段階)、ランク戦(対AI, ローカルラダー, BAN あり)、練習場、チュートリアル、観戦(AI vs AI)、リプレイ再生。
  - 観戦・リプレイ: シーク（巻き戻し・早送り・コマ送り）、速度 0.5〜8 倍、視界の切り替え（全体 / 各チーム）、自動カメラ、自由カメラ、情報パネル。
    オンラインでは観戦席（遅延付き）と、自分の死亡中に味方を見る機能がある。報酬・ランク・戦績の対象外（観戦の回数だけを通貨なしの実績にする）。
    設計は ARCHITECTURE.md「観戦」。
  - 追加モード（モバイルレジェンド風の選択画面に対応。すべてオフライン対AI）:
    - 乱闘(Brawl): 単レーン・ジャングル無し・ゴールド/XP 加速の 5v5。`MatchMode.brawl` + `MapDefinition.brawl`。短縮クロック 15 分。報酬あり・ランク非対象。
    - アーケード(Arcade): 遊べる変種モードのハブ画面（当面は乱闘）。
    - ライジング(Rising): 対AIの勝ち上がりラダー。固定ステージを順に攻略し、敵難易度と報酬が段階的に上がる。進行は `Profile.rising` に永続化。通常戦ベース。
    - AI対戦とカスタム(Custom): 陣営・側別難易度・マップ(標準/乱闘)を選んで起動。`MatchMode.custom`（標準マップ）。報酬・ランク非対象。
    - マジックチェス(Magic Chess): 簡易オートバトラー（8 人、ショップ・盤面配置・自動戦闘・ロールシナジー・HP 脱落）。独立シム `VelstriaCore/MagicChess/`。戦闘数値のみ既存の成長・軽減式を流用。
- マップは `config.mode` から決定論的に導出する（`MapDefinition.map(for:)`。リプレイはマップを保存しないため）。
- ストア: コスメ・ヒーロー解放のみ。AstralGem は StoreKit 2 の消耗型課金。競技戦闘力は一切販売しない。
- オンライン機能（フレンド/チャット/パーティ/招待/オンラインランキング）は Phase 2。`FeatureFlags.online == false` で導線を非表示。
- 開発期間の対戦テスト用に、リッスンサーバー方式のオンライン対戦（`FeatureFlags.lanMatch`、`MatchMode.online`）がある。
  同一 LAN / IP 直接入力、または部屋コード（中継サーバー経由。違う場所・違う Wi-Fi でも可）でホストの端末に繋ぎ、人間が占めない枠は AI。
  報酬・ランク・戦績の対象外。設計は ARCHITECTURE.md「オンライン対戦」。
- 決定論シミュレーションは将来サーバー権威（Swift on Server）へ流用できる構造にする。

## 1. 座標・時間
- シミュレーションは 2D 平面 (x, y)。単位 = マスターデータと同じ「ユニット」(射程 150/550、移動速度 ~250 と整合)。
- 描画: 100 ユニット = RealityKit 1 m。sim の (x, y) → world (x/100, 0, -y/100)。
- 固定 tick: 30 Hz (`Balance.tickRate`)。dt = 1/30 秒。描画は 60fps で補間。
- 時刻 `state.time` は試合開始からの秒。

## 3. 試合進行
- 状態: `loading → playing → ended`。`playing` 開始時刻 0。
- ミニオン: 0:20 に初回、以後 30 秒毎。1 ウェーブ = 近接 3 + 遠隔 3、3 ウェーブ毎に攻城 1 追加。10:00 以降は近接 +1。側レーン（top・bot）のミニオンは移動速度 −10%（中央レーンは通常。参照仕様 §3.1）。
- 勝利条件: 敵 Star Core 破壊。Core は各チームの基部塔が 1 本以上破壊されるまで無敵。
- タワーは同レーン内で外→内→基部の順にのみ攻撃可能（前段が残っている間は無敵）。
- 降参: 8:00 以降、人間プレイヤーが提案 → AI 味方は「チームゴールド差 ≥ 3000 またはタワー差 ≥ 3」の場合のみ賛成。過半数（3/5）で成立。60 秒 CD。
- 目標試合時間 10–18 分。

## 5. 戦闘計算（順序固定）
1. 無敵判定（Invulnerable / 保護中の構造物）→ 0 ダメージ
2. 生ダメージ算出: 通常攻撃 = 攻撃力 × (クリティカル時 1.75)。スキル = §6。
3. 与ダメ補正: 加算合計 (1 + ΣdamageBonus)（パッシブ・装備・ルーン・バフ）
4. 防御軽減: 物理 = × 100/(100+防御)、魔法 = × 100/(100+魔防)、確定 = 軽減なし。
   ヒーローの貫通（装備: `Stats.armorPenPct/Flat`・`magicPenPct/Flat`）は、構造物以外の相手の防御/魔防を **割合 → 固定値の順** に減らしてから式に入れる（下限 0。割合は装備間で重ならず最大値）。
5. 被ダメ軽減: × (1 − min(0.6, ΣdamageReduction))
   - ミニオンへのスキルダメージ（物理・魔法・確定とも）は防御軽減の後に ×0.2（`Balance.Skills.minionDamageMultiplier`）。スキル倍率（×2.6〜4.0）が大きく、Lv1 でも 1 発でウェーブが消えていたため。装備なしの Lv1〜13 なら、どのスキルも 1 発ではミニオンを倒せず、近接ミニオンは中央値のスキルで約 3 発かかる（参照ゲームは少なくとも 2 回）。通常攻撃・装備・バトルスペルは対象外。固定の上限ではなく倍率なので、スキルごとの強弱はミニオン相手にも残る。
6. シールド吸収（古いものから）→ HP 減算
7. ライフスティール/スペルヴァンプ回復
8. HP ≤ 0 → `pendingDeaths` に積む（キル・アシスト判定はそこで一括）
- CC: Slow = 移動速度 −30%/1.5s（Ult は −45%/2.0s）、Root = 1.0s（Ult 1.5s）、Stun = 0.75s（Ult 1.25s）、
  Knockback = 250 ユニット押し出し(0.25s) + 0.25s スタン。CC 耐性（浄化/CC無効）中は無効。
- スロー重複は最大値のみ適用。移動速度下限 100。
- 攻撃ボタンの対象選択（`CombatSystem.selectTarget` / `selectAttackTarget`）:
  - 中央ボタンの優先対象は MLBB の「優先して狙う対象」と同じ 3 択（`GameSettings.centerAttackPriorities`、既定は実質低HP）: HP割合が低い敵（`.lowestHealthPercent`）/ 実質HPが最も低い目標（`.lowestHealth`）/ 最も近い目標（`.nearest`）。上下のボタンは従来どおりタワー・ミニオン優先など。
  - ヒーローロック（既定オン、中央ボタンのみ。コマンド `attackNearestWith`）: 射程内に敵ヒーローがいれば、ヒーローだけの中から優先度で選び、追撃（下記）も有効。オフなら全候補から優先度で選び、追撃しない。
  - アクティブモンスターの判別（既定オフ、中央ボタンのみ）: 誰も狙っていない（戦っていない）中立モンスターは、ほかに候補があれば外す。MLBB の同名設定の厳密な再現ではなく、寝ている野営地を起こさないための近似。
  - 旧版で中央ボタンに選んでいた「ヒーロー / ミニオン / タワー優先」は、設定の読み込み時に実質低HPへ移す。
  - 優先度「実質低HP」（`.lowestHealth`）は、残り HP ではなく、攻撃者のダメージ構成（スキルの物理・魔法の割合）に対する防御・被ダメ軽減・シールドを含めた「倒すのに要るダメージ」が最も少ない敵を選ぶ。
    スキルの大半がトゥルーダメージのヒーローは防御を無視できるので、従来どおり残り HP（hp + シールド）が最も少ない敵（現在そのデータ上のヒーローはいない）。攻撃者の装備の貫通力も防御に反映する。
  - 追撃: 敵ヒーローを狙う（攻撃ボタンの選択・通常攻撃の発射）たびに、その対象を `HeroData.attackStickyTargetID` に記録する。2 秒（`Balance.attackStickyWindow`）以内に押し直すと、
    その敵ヒーローが射程 + 1200（`attackStickyChaseExtra`）以内で狙えるかぎり、射程内により倒しやすい別の敵ヒーローがいない限り同じ対象を優先して追う（射程外でも、ミニオンと敵ヒーローの間で対象が切り替わり続けない）。
- アシスト: 死亡前 10 秒以内に被害者へダメージ/CCを与えた敵ヒーロー、または被害者に攻撃されていた味方を回復/シールドしたヒーロー。

## 6. スキル
- 各ヒーロー: Passive + Skill1/2 + Ultimate（スキル枠は 4 つ。Skill3 は廃止）。スキル挙動は `SkillCatalog` がマスター値(range/radius/cc/damage)とロール・スロットからアーキタイプを割当てる。
- ランク: 基本スキル最大 4、Ult 最大 3（Lv 4/8/12 で習得可能）。Lv1 で 1 ポイント、以後レベル毎 +1。
- 自動習得（既定 ON）: Ult > Skill1 > Skill2 の順で可能なもの。
- ダメージ = base_damage × (1 + 0.30×(rank−1)) + scaling_attack × 総攻撃力 × 0.6 + scaling_power × 魔力
- CD = cooldown_sec × (1 − 0.06×(rank−1)) × (1 − CD短縮)。CD短縮上限 40%。**スキルのクールダウンは Mobile Legends と同じ秒数**（調整倍率 `Balance.Skills.cooldownScale` = 1.0。2026-10 に 0.5 から変更）。キット（H025–H034）のヒーローは MLBB の秒数をランクへ線形補間した値（`docs/kits/*.md`）。
- 調整倍率: ダメージ ×[Skill1 4.0 / Skill2 3.0 / Ult 2.6]、回復・シールド系 ×2.4。1v1 の TTK の帯は `SkillBalanceTests`（2.5〜22 秒、全員総当たりで外れは 2% 以内）。CD を MLBB の秒数にしたときダメージ倍率は上げなかった: スキル 1 発のダメージはすでに MLBB 以上（汎用のスキル1 は Lv1 で約 900 = MLBB の 2〜3 倍）で、上げると MLBB から遠ざかるため。代わりに TTK の帯を MLBB の装備なしの 1v1（15〜22 秒前後）に合わせて上限 15 → 22 秒へ広げた（全員総当たりの中央値は Lv1 10.0 → 13.6 / Lv6 5.3 → 8.7 / Lv12 5.7 → 9.2 秒）。
- コスト = cost（Mana/Energy）。Energy ヒーローは cost × 0.6。
- ダメージ種別はヒーロー毎（マスター damage_type）。
- アーキタイプ（`SkillArchetype`）:
  - Skill1「〜式・一閃」: 近接 = 前方扇形(半径 range, 角 90°)、遠隔 = 直線スキルショット(最初の敵に命中、幅 radius×0.5、弾速 1600)
  - Skill2「星環シフト」: 近接 = 指定方向へ突進(距離 range+100)し着地点 radius に効果、遠隔 = 短距離ブリンク(350)+次の通常攻撃強化(+50% スキル基礎値)
  - （旧 Skill3「境界制圧」の地点 AoE / 回復ゾーン / 自身中心 AoE は、スロットとしては廃止。アーキタイプ実装 `groundAoE` / `healZone` / `selfAoE` は Ult とヒーロー固有スキルの土台として残す）
  - Ultimate（ロール別）:
    - Vanguard: 跳躍突撃（最大 range+200、着地 AoE radius×1.4 + CC）
    - Duelist: 連続斬り（範囲内の敵ヒーローを 3 回攻撃、各 45%）+ 自身 25% 被ダメ軽減 2s
    - Ranger: 貫通大矢（直線、長さ 2000、幅 radius、全ヒット、CC）
    - Arcanist: 大範囲遅延 AoE（1.0s 予告、radius×1.8）
    - Support: 味方全体（1500 以内）回復 base_damage×1.2 + シールド、周囲の敵に CC
    - Assassin: 対象指定ブリンク（最寄りの敵ヒーロー range 以内）+ 失ったHPの 12% 追加ダメージ
- パッシブ（ロール別 + ヒーロー固有係数 k = 1.0 + 0.02×(番号 mod 5)）:
  - Vanguard: HP 40% 未満で最大HP 15%×k のシールド（CD 20s）
  - Duelist: 通常攻撃命中毎に攻撃速度 +6%×k（最大 5 スタック、3s 持続）
  - Ranger: 4 発毎の通常攻撃が必ずクリティカル（1.75×k 倍）
  - Arcanist: スキル命中で他スキル CD −0.6s×k（1 キャストにつき 1 回）
  - Support: スキル使用時、最も HP 割合の低い味方（800 以内）を 40+10×Lv×k 回復
  - Assassin: 草むら/ステルス解除後 3 秒以内の最初のダメージ +30%×k、キル/アシストで全 CD −30%

## 8. 経済・成長
- 開始 Gold 300。パッシブ Gold 毎秒 3（0:20 以降）。
- モード別の加速（`Balance.Economy.goldScale`/`xpScale`）: 乱闘は Gold・XP とも ×2.0、他モードは ×1.0。`grantGold`/`grantXP` の 1 箇所で適用（練習場の無限 Gold には適用しない）。
- Gold/EXP レーン補正（序盤 0〜5:00）: Gold レーンのミニオンは Gold ×1.25、EXP レーンのミニオンは XP ×1.40（`Balance.Economy.goldLaneGoldBonus` / `expLaneXPBonus` / `laneBonusEnd`）。
  参照仕様は側レーンの攻城ミニオンだけ +45% / +35% だが、VELSIA の攻城は 3 ウェーブに 1 体なのでウェーブ全体へ換算した暫定値（Phase 1 の計測で調整）。
- ミニオン/モンスター Gold はラストヒットのみ。XP は 1400 以内の味方ヒーローで等分（1 人なら ×1.0、2 人以上は合計 ×1.3 を等分）。
- ヒーローキル: 基本 300。被害者の連続キル数 s ≥ 2 で +60×(s−1)（上限 +480, シャットダウン）。被害者が連続死亡中 d ≥ 2 で −15%×(d−1)（下限 100）。初キル +100。
  アシスト: バウンティの 50% をアシスト人数で等分（1 人最低 40）。
- XP: ヒーローキル = 100 + 30×被害者Lv（キラー 100%、アシストは 1400 以内で 60% を等分）。
- 必要 XP（Lv→Lv+1）: 240, 270, 300, 350, 400, 450, 500, 550, 600, 650, 700, 750, 800, 850（累計 Lv4 = 810、Lv15 = 7410）。
  序盤を軽く（Lv1→4 が +30 刻み）、Lv4 以降は +50 刻み。旧: 260 から +40 刻み（Lv4 = 900、Lv15 = 7280）。参照仕様に Lv 別 EXP 表が無いため ML の実値ではなく、「2:00 で Lv4」の目標（`REFERENCE_GAP.md` §9）に寄せた暫定の設計値。
- リスポーン: 4 + 2×Lv 秒、12:00 以降 ×1.25、上限 40 秒。
- 装備: 6 枠。購入は常時可能（モバイル標準）。靴（移動）は 1 足まで。合成は素材の素材までたどり、所持している素材（どの段でも）を消費してその価格を引いた差額を払う（`Balance.minCombineCostRatio` = 0、MLBB と同じ）。売却 = 投資額の 60%。
- 装備は Mobile Legends の装備図鑑（日本語クライアント、パッチ 2.2.16 / 2026-09）をそのまま写した総入れ替え（2026-10）。名前・価格・レシピ・能力値・固有パッシブは実機の図鑑の表記に合わせ、写っていない数値は MLBB Fandom の `Module:Equipment/data`（2026-09-24）とパッチノートで補った。
  - 正本は `tools/equipment_spec.mjs`（`node tools/equipment_apply.mjs` が `master_runtime.json` の `equipment` と英語文の出典 `tools/equipment_spec.json` を書く。`--check` で差分検査）。英語の名前・説明は `tools/gen_master_en.py` が `master_en.json` に書く。
  - 92 個: 攻撃 34（EQ101〜134）、魔法 25（EQ201〜225）、防御 25（EQ301〜325）、移動 8（EQ401〜408）。ID は図鑑のタブと並び順（完成品 → 素材 → ポーション）。複数のタブに出る装備（ウィンタークラウン・フリーティングタイム・天空の刃・エキスパートグローブ）は `also_in`。
  - ヒーロー専用の装備（希望のランタン・希望の花・投擲禁止・投擲許可）は入れていない。
  - Tier: 3 = 完成品、2 = 合成品（完成した靴も 2）、1 = 基本素材。ポーション（パワー・マジック・ロック、各 1500）は消耗品: 買うとすぐ 120 秒の効果、所持枠を使わない、効果は 1 つだけ（`ItemRuntime.potionID`）。
  - 能力値: 物理攻撃・魔法攻撃・**適応攻撃**（装備で増えた攻撃力と魔力の多い方。同じならヒーローのスキルの種類）・HP・**MP**（Mana のヒーローだけ）・物理/魔法防御（混合は両方）・移動速度（固定・%）・CD 短縮・攻撃速度・クリティカル率/ダメージ・吸血（混合は通常攻撃とスキルの両方）・物理/魔法貫通（割合・固定）・HP/MP 回復・**コントロール時間短縮**（上限 70%）・**減速軽減**・受ける回復・**クリティカルダメージ軽減**・ダメージ軽減。
    `unique_stats`（固有の能力値）は重ならず、能力値ごとに最大値。割合の貫通（撃砕・魔法の聖剣）も最大値。
  - 固有効果は `ItemDef.effects`（`ItemEffectKind` と係数、1 つの装備が複数持つ）。同じ種類は Tier の高い装備の 1 つだけ働く（MLBB のユニークパッシブ）。状態はヒーローごとの `ItemRuntime`（配列。決定論のため辞書は使わない）。
    能力値だけで決まるもの（射程・魔力の割合・クリティカルの換算・竜鱗）は `ItemEffects.applyStatEffects`、スタックや一時的な強化は `applyRuntimeStats`（`StatCalculator` が毎回足す）。
  - 主なもの: 確定ダメージ（聖裁・審判・危機・破滅・雷撃・闘志）、貫通の上乗せ（破壊者・魔法破り: 対象の防御 1 につき 0.1%）、即死（天空の刃: HP 4〜12% 未満）、
    復活（イモータル: 倒されて 2.5 秒後にその場で HP 16% + シールド）、回復阻害（生命の災い）、継続ダメージ（焼灼・燃える魂）、反射（刃の鎧）。全一覧と数値は `tools/equipment_spec.mjs`。
  - **アクティブ**: ウィンタークラウン（2 秒 凍結・無敵、CD 100）とナチュラルウィンド（物理ダメージ無効 2 秒・射手以外は 1 秒、CD 90）は `PlayerCommand.useItemActive`（HUD のボタン。ボットは HP 30% 未満で使う）。
  - 装備の追加ダメージは `DamageSource.item`（通常攻撃の命中・吸血・ほかの装備の効果を起こさない）。
- 靴の祝福（8.1）: ジャングル・ロームは装備ではなく、持っている 1 足の靴に付ける祝福。
- ルーン: 1 ページ = メインパス 1 つ + 各 Tier から 1 個（計 3 個）。効果 X%（effect 文字列の %）:
  Valor 攻撃力 +X%、Arcana 魔力 +X% とスキルダメ +X/2%、Resolve 最大HP +X% と防御/魔防 +X%、Cunning 移動速度 +X/2% と CD短縮 +X/2%、Harmony HP/Mana 回復 +3X% と回復量 +X%

## 9. 視界
- チーム視界 = 味方ユニットの視界円の合成。格子 200 ユニット (60×60)、10Hz 更新。
- 草むら: 草むら内のユニットは、同じ草むら内に敵が居るか 300 以内に敵が居ない限り敵チームから不可視。複数の矩形からなる草むらは、どの矩形にいても同じ草むら（`BrushArea.bush`）。
- ステルス: 真視界（タワー 750、泉）内か 250 以内の敵に対してのみ可視。
- 視界外の敵はクライアントに描画しない（HUD・ミニマップも同様）。最後に見えた位置はミニマップに 3 秒残像。
