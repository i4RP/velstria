# App のプライバシー（プライバシー栄養ラベル）

ASC > App のプライバシー の回答。オンライン対戦（`FeatureFlags.lanMatch == true`）とフレンド機能を含む版の申告方針。
結論: **「データを収集する」**。収集するのは **ID > ユーザ ID** だけ（ユーザーに関連付けられる・トラッキングなし・目的は App の機能）。

> 2026-10-12 に見直し。以前の「データを収集しない」は、中継が何も保存しない前提だった。フレンドの受信箱（`relay/src/inbox.ts`）が
> 鍵のハッシュと最後に接続した日時を（本人が消すか、1 年接続しなくなるまで）、不在の相手宛ての申請（差出人のフレンドコードと表示名）を
> 受け付けから 14 日保存するので、Apple の定義の「収集」に当たる。

## 回答

| 質問 | 回答 |
|---|---|
| お客様またはサードパーティパートナーは、この App からデータを収集しますか？ | **はい、この App からデータを収集します** |
| プライバシーポリシー URL | `metadata/ja/privacy_url.txt` / `metadata/en-US/privacy_url.txt` |
| ユーザーのプライバシー選択 URL | `metadata/ja/privacy_choices_url.txt` / `metadata/en-US/privacy_choices_url.txt`（/privacy-choices。`tools/asc.mjs` は送らないので ASC で手入力する） |
| トラッキング | なし（App Tracking Transparency 不使用、`NSUserTrackingUsageDescription` なし） |

### 収集するデータの種類

| 種類 | 何が該当するか | ユーザーに関連付け | トラッキング | 目的 |
|---|---|---|---|---|
| ID > ユーザ ID（User ID） | フレンドコード（8 文字）と表示名（スクリーンネーム）。受信箱の持ち主を確かめる鍵の SHA-256 と最後に接続した日時、不在の相手宛てに預かる申請の差出人のフレンドコード・表示名 | **はい**（フレンドコードに結び付く） | いいえ | **App の機能**（フレンド申請・招待の配送、在席の表示） |

上記以外の種類（連絡先情報、位置情報、購入、使用状況データ、診断、その他）は「収集しない」と答える。根拠は次節。

## 根拠

Apple の定義では、データを端末外へ送り、開発者または第三者のパートナーが、リアルタイムの要求の処理に必要な時間を超えて利用できる状態にすることが「収集」。

| データ | 送信先 | 保存 | 判定 |
|---|---|---|---|
| フレンドコード・受信箱の鍵（接続時） | 中継の受信箱（Cloudflare Workers + Durable Objects） | 鍵の SHA-256 と最後に接続した日時を、本人が消す（設定 > プライバシー の「フレンドサーバーのデータを削除」「全データを削除」）か、1 年接続しなくなるまで保存。消したコードは「消した印」だけを残す | **収集**（ユーザ ID） |
| フレンド申請・承認（差出人のフレンドコード・表示名） | 中継 → 相手の受信箱 | 相手が不在なら最大 20 件・受け付けから 14 日（期限の時刻に alarm で消す。同じ申請が届き直しても延ばさず、アプリは申請から 14 日を過ぎたら送り直さない） | **収集**（ユーザ ID） |
| パーティ招待・返事、在席の問い合わせ | 中継（リアルタイム） | 保存しない（不在の相手には届けずに捨てる） | 収集しない |
| 部屋コードでの対戦データ（名乗り・部屋の状態・入力・スナップショット） | 中継 → 相手の端末 | 保存・ログ出力しない（`wrangler.jsonc` の `observability.enabled: false`）。部屋ごとの参加者番号の採番だけ、ホストが去って 10 分で削除 | 収集しない |
| 同じネットワークでの対戦データ、Bonjour の広告 | 端末どうし（開発者は受け取らない） | 開発者は保持しない | 収集しない（開発者・パートナーが受け取らない） |
| 接続元の IP アドレス | Cloudflare（インフラ） | Worker のコードは読まない。Cloudflare のプラットフォーム側の扱いは Cloudflare のポリシー | 収集しない（開発者が利用しない。下の「要判断」） |
| プロフィール・リプレイ・購入台帳・年齢区分 | 端末内だけ | — | 収集しない |
| App 内課金 | Apple | Apple のプライバシーポリシーの対象 | 申告の対象外 |
| クラッシュレポート | 利用者が「App デベロッパと共有」を許可した時に Apple 経由 | — | 申告不要（サードパーティの SDK なし） |
| サポート・通報のメール（メールアドレス、本文、端末情報・プレイヤー ID） | 利用者が自分のメールアプリから送る | 運営のメール | 下の「要判断」 |

- 他の参加者の端末に残る表示名（オンライン対戦のリプレイ・フレンド一覧）は、開発者やパートナーが受け取らないので収集に当たらない。
- 中継に保存・解析を足す場合、受信箱の保存内容を変える場合は、このラベルとプライバシーポリシーを同時に見直す。

### 要判断（人が決める）

- **サポートのメール**: 任意開示の条件（まれで主機能でない・任意・利用者が送る内容を明確に分かったうえで毎回自分で送る）に当たるとみて申告しない案。
  当たらないと判断するなら「連絡先情報 > メールアドレス」と「その他のユーザコンテンツ」（目的: App の機能〈カスタマーサポート〉、関連付けあり）を足す。
- **IP アドレス**: 開発者は記録も利用もしないが、Cloudflare（サードパーティのパートナー）がプラットフォームとしてどの程度保持するかは未確認。
  Cloudflare のデータ処理契約（DPA）とログの保持を確かめ、保持がリアルタイムの処理を超えるなら申告を見直す。
- **13 歳未満**: 年齢区分 .under13 と未申告はオンライン機能（フレンドを含む）を使えず、受信箱へ繋がない（`OnlineAccess`・`FriendHub.start`）。
  年齢区分は自己申告なので、偽った申告までは防げない。ラベルの問題ではないが、COPPA の扱い（プライバシーポリシー運用メモ）と合わせて確認する。

## プライバシーマニフェストとの対応

`App/Resources/PrivacyInfo.xcprivacy`（上の申告と同じ内容。`tools/privacy_audit.py` と `AppStoreAssetsTests` が一致を確かめる）:

| キー | 値 |
|---|---|
| `NSPrivacyTracking` | false |
| `NSPrivacyTrackingDomains` | 空 |
| `NSPrivacyCollectedDataTypes` | **`NSPrivacyCollectedDataTypeUserID`**（`NSPrivacyCollectedDataTypeLinked` = true、`NSPrivacyCollectedDataTypeTracking` = false、`NSPrivacyCollectedDataTypePurposes` = [`NSPrivacyCollectedDataTypePurposeAppFunctionality`]） |
| `NSPrivacyAccessedAPITypes` | UserDefaults: `CA92.1` / File timestamp: `C617.1` / System boot time: `35F9.1` |

- System boot time（`ProcessInfo.systemUptime`）はオンライン対戦の RTT の計測にも使い、RTT は部屋の参加者に配られる。`35F9.1` は「アプリ内のイベント間の
  経過時間」なら端末外へ送ってよい例外があるので理由コードは変えなくてよい（マニフェストのコメントにその旨を書いた）。
- Disk space API は未使用のため宣言していない。使用を追加したら `python3 tools/privacy_audit.py` がエラーにするので理由コード（例 `E174.1`）を足す。
- 外部 SDK を追加する場合は、その SDK のプライバシーマニフェストと署名を確認し、収集データがあればラベルを更新する。

## 変更時のルール

解析・広告・クラッシュ収集 SDK、中継サーバーでの保存の追加・変更、クラウド保存などを入れる場合は、リリース前に
1) 栄養ラベル（本書）、2) `PrivacyInfo.xcprivacy` の `NSPrivacyCollectedDataTypes`、3) `docs/legal/privacy_policy_*.md`・`external_transmission_*.md`・
`privacy_choices_*.md` を同時に更新する。
