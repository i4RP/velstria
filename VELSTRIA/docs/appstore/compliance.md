# 輸出コンプライアンスとコンテンツの権利

## 輸出コンプライアンス（Export Compliance）

| 質問 | 回答 |
|---|---|
| App は暗号化を使用していますか？（免除対象を含む） | **いいえ**（`ITSAppUsesNonExemptEncryption = NO` を Info.plist に設定済み） |
| フランスでの配信に必要な書類 | 不要 |

- アプリ自身は暗号化アルゴリズムを実装していない（CommonCrypto・独自暗号の使用なし）。CryptoKit は TesterAccess の SHA-256（ハッシュ）にだけ使う。
  ハッシュは暗号化（データの秘匿）ではないので、判定に影響しない。
- 通信は次の 3 つ。いずれも OS が提供する暗号化を使うか、暗号化しない。OS に組み込まれた暗号化の利用は米国輸出規制上の免除対象。
  - StoreKit 2（OS の HTTPS）
  - オンライン機能の中継サーバー（`URLSessionWebSocketTask` の wss。OS の TLS）
  - 同じ Wi-Fi の対戦（Network.framework の TCP。`NWParameters(tls: nil)` で暗号化しない）
- Info.plist にキーを設定済みなので、アップロードのたびに ASC で質問に答える必要はない。
- 独自の暗号化（リプレイ署名・通信の独自暗号・LAN の TLS を独自の鍵で行う等）を加える場合は判定をやり直し、必要なら年次自己分類レポートを提出する。

## コンテンツの権利（Content Rights）

| 質問 | 回答 |
|---|---|
| 第三者のコンテンツを含む、表示する、またはアクセスしますか？ | **いいえ** |

> 要判断（2026-10-12）: オープンソースのフォント・ライブラリ（ライセンスに従って同梱）と、オンライン機能で他の利用者の表示名を表示することを
> 「第三者のコンテンツ」とみるなら「はい」（必要な権利を有する）と答える。どちらにするかを提出前に決める。

- ヒーロー名・スキル名・世界観・UI・アイコンはすべてオリジナル。仕様書の「参考アプリ監査」は機能の概念を抽象化したもので、
  他作品の名称・数値・画像・音声は使用していない（仕様パッケージ README「参考機能は概念のみ抽象化し、名称・数値・UI・世界観は独自化」）。
- アイコン・起動ロゴは VELSIA オリジナルのキャラクター H002 と星環のシルエット紋章を用いた自社管理素材。
- フォント: iOS のシステムフォントに加え、Chakra Petch と Cinzel（いずれも SIL Open Font License 1.1。ライセンス本文を App/Resources/Fonts に同梱し、
  クレジット画面に表記）を同梱している。
- オープンソースのライブラリ: Effekseer（MIT）を静的リンクしており、その中に LLGI（zlib）と stb_image（MIT / パブリックドメイン）を含む。
  著作権表示とライセンス本文は公開サイトの /licenses（docs/legal/licenses_*.md）と、アプリのクレジット画面（`CreditsCatalog.openSource`。
  Effekseer・stb_image は MIT、LLGI は zlib の本文。AppTests の OnlineSafetyTests で docs/legal/licenses/ と一致を確かめる）に載せた。
- 音源: BGM と効果音の一部は CC0 1.0 の素材（Kenney・OpenGameArt.org）を加工したファイルを同梱（出典は docs/audio/SOURCES.md とクレジット画面「音楽・効果音」）。MLBB など他作品の音は使っていない。そのほかはコードで合成。
- 3D モデルを Meshy・Tripo 等の生成 AI で作る場合: 商用利用が許諾されるプランで生成し、生成日・プロンプト・プラン・利用規約の版を
  `VELSTRIA_復元版パッケージ/meshy/` のプロンプト ID と紐付けて記録する。既存 IP・実在人物・他社キャラクターに似せるプロンプトは使わない。
  現状、ヒーロー・構造物（Tripo）、ステージの小物（Meshy）、ポートレート等の 2D（Codex CLI の画像生成）の生成時のプランと規約の版の記録は
  リポジトリで確認できない（未確認）。無料プランの出力に表示義務（CC BY 等）があれば /licenses に追記する。
- BGM・効果音を外部から調達する場合は、商用・アプリ内再配布が可能なライセンスであることを確認し、クレジット画面（`Route.credits`）に表記する。
- 商標: 「VELSIA」「ベルシア」の商標調査・出願を公開前に行うことを推奨（アプリ名の他者権利侵害による却下・差し止めの防止）。

## 米国の州の年齢確認法（要判断）

> 要判断（2026-10-12）: テキサス州（SB 2420, App Store Accountability Act）、ユタ州、ルイジアナ州などの年齢確認・保護者の同意に関する州法は、
> App ストアと開発者に、利用者の年齢区分の受け取りと、未成年者の保護者の同意の確認・取り消しへの対応を求めている（施行日・範囲は州ごとに異なる）。
> 本アプリは自己申告の年齢区分（端末内）で 13 歳未満のオンライン機能と課金の上限を制御しており、Apple の仕組みは使っていない。
> 次のどれにするかを、公開前に弁護士に確認して決める。

- Apple の仕組みを実装する: Declared Age Range API（年齢区分の受け取り）、Significant Change API（PermissionKit。オンライン機能の追加など
  大きな変更の時に保護者の同意を求める）、StoreKit の `ageRatingCode`、App Store Server Notifications の `RESCIND_CONSENT`（同意の取り消しで
  オンライン機能・課金を止める）。年齢区分の自己申告（`AgeBracket`）との関係も決める。
- 対象の州を配信地域から外す（ASC の配信地域では州単位で外せないため、米国全体の扱いになる点に注意）。
- 現状のまま公開する（法的なリスクを受け入れる）。

いずれの場合も、保護者の方へ（/parents）・プライバシーポリシー第 13 節・[release_checklist.md](release_checklist.md) を合わせて直す。
