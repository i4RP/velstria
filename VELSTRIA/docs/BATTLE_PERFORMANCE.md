# iPhone バトル性能の契約

追加コンテンツの総数ではなく、1 試合に登場する内容と画面付近の表示量で描画負荷を決める。
同時に戦うユニットや地形判定そのものを増やす場合、CPU 負荷が一定とは保証できない。
その変更は別途、シミュレーション予算と比較計測で判断する。

## 実装ルール

- ゲーム判定・通信・霧の可視判定を描画の間引きに連動させない。画面外でも位置と生死は更新する。
- ユニットの詳細表示は `RenderFrame.needsDetail` を共通入口にする。画面端には高さ・影・移動の余白を持つ。
  画面外では骨格、バー、状態表示を更新しない。観戦の追従・カメラ移動・一時停止・シークで再表示できること。
- 新ヒーローは共通 `HeroVisual` / `UnitLayer` を使う。個別の毎フレームタイマーや全キャラ走査を追加しない。
- メッシュ、テクスチャ、文字メッシュ、マテリアル、エンティティはロード中に準備し、プレイ中は再利用する。
  新しい生成経路は `AssetLedger.record` を必ず通す。試合に登場しないヒーローのモデル・演出はロードしない。
- 装飾エフェクトにはプールだけでなく、予約数・1 回の再生数にも上限を設ける。超過は装飾を省略する。
  攻撃範囲・着弾予告・当たり判定を省略してはいけない。`SkillFXPlayer` の上限をキャラごとに増やさない。
- ステージは `StagePrep` の背景準備と材質別チャンク結合を使う。小物ごとの Entity や Timer を増やさない。
  テクスチャは既存のアトラスとサイズ上限を守り、新ステージの追加を全ステージの同時ロードにしない。
- HUD は既存の 15 Hz スナップショット更新を使う。入力とカメラの追従は描画周期を維持する。
- ダメージ数字などの投影は `CombatTextProjection` にカメラをフレームごとに一度渡す。
  表示数に比例した `ARView.project` 呼び出しを追加しない。カメラの垂直 FOV・姿勢・画面サイズを共有する。
  カメラの投影方式を変える場合は地面四隅との往復テストも更新する。

## 予算と検査

| 対象 | 基準・検査 |
| --- | --- |
| 60 fps | 1 フレーム 16.67 ms、アプリ CPU work の p95 は 8 ms 以下を目標 |
| シミュレーション | Release の `CombatPerformanceTests`（既存基準 1 ms/tick 未満） |
| キャラ | `HeroModelTests` / `SkinnedHeroModelTests` の三角形・Entity 予算 |
| スキル | `SkillFXTests` の全レシピ・粒子・寿命・live 生成予算 |
| 地形 | `StageTests` の結合・配置・三角形予算 |
| 戦闘中の生成 | `PerfReport.ledger.live` とサンプルを確認。新しい生成の増加は要修正 |

計測は同一端末、Release、同じ seed・画質・速度・時間で比較する。最低 65 秒、集団戦や後半は
`tools/perf_run.sh --seconds 150 --speed 4 --quality medium --out build/perf/after.json` を使う。
自動画質調整の履歴も保存し、画質低下による FPS 上昇と CPU の改善を区別する。
シミュレータの FPS は iPhone の GPU 性能の証明に使わない。

実機では同じ起動引数で Instruments の Time Profiler / Animation Hitches / Metal を採取する。
`Battle` カテゴリの `sync.units`、`sync.map`、`sync.projectiles`、`sync.effects`、`sync.fog` が処理の入口。
`sync.effekseer` は既存の work 集計の外で実行される追加描画の CPU 時間。各区間は JSON の
`syncWork` に呼び出し数・合計 ms・最大 ms を保存する（平均 = 合計 ÷ 呼び出し数）。GPU 時間は含まない。
work が高い場合は CPU、work が低いのに frame が遅い場合は GPU・描画エンジン・OS 待ちを調べる。
後者だけで GPU が原因と断定しない。温度、低電力モード、メモリ、透明描画の重なりも併記する。

## 2026-10-09 の調査と変更

iPhone 17 Pro シミュレータ / iOS 26.3.1 / Release / medium 開始 / 60 fps / 同一観戦 seed / 65 秒。
既存の自動画質調整は有効。別の起動済みシミュレータも動いているため、GPU とフレーム時間は特に参考値。
変更前は `10ee0b4` の描画処理、変更後は本変更（実機モニター統合前）。
[変更前の生データ](perf/2026-10-09/before.json) / [変更後の生データ](perf/2026-10-09/after.json)。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 戦闘計算平均 ms | 0.12 | 0.12 |
| 描画同期平均 ms | 0.70 | 0.47 |
| 数字オーバーレイ平均 ms | 2.23 | 0.03 |
| CPU work p95 ms | 13.25 | 1.00 |
| フレーム p95 ms | 50.25 | 50.25 |
| フレーム p99 ms | 111.50 | 66.75 |
| ピークメモリ MB | 619 | 635 |
| 戦闘中の記録対象アセット生成 | 0 | 0 |

数字ごとの `ARView.project` を廃止し、カメラ姿勢を共有する投影計算へ変更。画面外のユニットの詳細表示を停止し、
位置・生死・霧の判定を維持した。装飾スキル演出は 1 再生 64 合図、遅延予約は全員合計 512 件に制限した。
既存のキャラ・ステージ予算テストも配信 CI に追加した。

CPU 側の待ち時間は減ったが、フレーム p95 は改善していない。実機 60 fps 達成を示す結果ではない。
次の実機調査では Effekseer の追加描画（今回平均 1.45 ms、既存 work 集計外）、RealityKit/GPU、
透明エフェクト・ステージ描画を優先する。メモリ削減も今回の改善対象には含めない。
別途 Mac の Core Release テストでは 16,200 tick、平均 0.123 ms/tick、決定論テストも通過した。
