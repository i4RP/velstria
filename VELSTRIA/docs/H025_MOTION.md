# H025 ルミナのモーション

対象は「月弦のルミナ H025」（`Kit_H025` の Miya 相当）。`HeroAssetLibrary` が
`Hero_H025.usdz` を読み、`SkinnedHeroModel` が再生する。マイヤという別IDは追加していない。
初版導入前のmainにはH025のUSDZがなく、実際は手続きモデルへのフォールバックだった。
初版で別worktreeの完成モデルを同梱してスキンメッシュ経路を有効にした。

## 2026-10-23 の画面収録への合わせ込み

参照はユーザー提供の `ScreenRecording_10-23-2026 19-12-01_1.mov`（7.463秒）。
SHA256: `8f1ac5888b20b6506b11da94d7ac189b9e631564538aeb81c16cb5949ac5cd87`。
動画そのものはリポジトリに同梱しない。

冒頭は弓を腰の横へ下げた走行。1.7秒台から奥義で踏み切り、腕を開いて少し浮き、
2.3秒台に接地する。透明なまま向きを変えて移動し、6.4秒前後から弓を斜め上へ掲げて射撃する。
画面に見える輪郭と時刻を基に、既存65骨へ手付けで再現した。動画から3D骨格を取得したものではなく、
隠れた関節・奥行きには推定を含む。完全一致や実機での一致は未確認。

- 待機・歩行・走行は、両手で弓を胸の前へ固定する姿勢から、左手で腰の横に持ち、右腕が歩調に合わせて動く姿勢へ。
  走行は基準3.375 m/sで0.60秒/周期、歩行は1.2 m/sで0.90秒/周期。支持脚は実際の移動速度を打ち消す。
- S2 `h025_skill2`: 斜め上へ掲げる → 引き絞る → 約0.27秒で離弦 → 0.60秒で復帰。
  構え始め6.38秒前後と矢が見える6.65秒前後から8/30秒に設定し、発射の光と矢も同時刻へ。
  スキル詠唱でも弦が指から離れる。通常攻撃の発射イベントは待たない。
- 奥義 `h025_ultimate`: 小さな踏み切り → 両腕を開いた浮き姿勢 → 接地 → 0.70秒で復帰。
  最初の16フレームだけ脚もクリップを使い、移動入力中に跳躍が消えるのを防ぐ。
- S2・奥義は先頭から再生し、手続きモーションの復帰時間も同じ長さにする。
  通常攻撃は既存の発射時刻を維持し、始終だけ新しい待機姿勢につなぐ。

生成は既存の `author_h025_motion.py` の `reference_pose`。追加のAPI利用・モデル再生成はない。
モデル、ゲーム上の位置・旋回・速度・隠密の時間・当たり判定・演出予算は変更しない。
映像中の移動経路や方向転換は操作によるものなので、キャラの骨格へ固定の移動を入れない。
既存の表示更新とH025専用クリップの読み込みを使い、毎フレームの生成・タイマーを追加しない。

Blender 5.2.1 / macOSで全6クリップを書き出し、ループの継ぎ目は0°、手足の到達範囲の切り詰めは0 mm。
S2・奥義も `preview_h025_motion.py -- --only skill2` / `--only ultimate` で確認できる。

検証: Xcode 26.2 / iPhone 17シミュレータ（iOS 26.3.1）/ Debug。
`HeroMotionClipTests` 34件、`HeroModelTests` 19件、`SkillFXTests` 46件、
`SkinnedHeroModelTests.testBundledHeroAssetsMeetContract` 1件が通過（再実行を含む）。
実際のRealityKitの走行展示は65秒の連続再生でクラッシュなし。実機FPS・完全一致の検証ではない。

## モデルと素材

完成モデルは gold-lumina worktree の `33788ac` 由来。元USDZの SHA256 は
`a15a81e99a8166c1f9f6f9bb0ce42c02688b7f81a1c20bfc6058bdae32726d0a`。
元リグは23骨で指がなく、握りと弦を離す動作を表現できないため、同じ形状をTripoへ渡して65骨へ補修した。
モデルの再生成はしていない。3枚の元テクスチャはバイト単位で一致し、9,353三角形を維持。
リグ前後の対応する28,059三角形頂点の最大位置差は1.28µm（座標変換の丸め）。
表情・顔・衣装・体形を保持し、スキンウェイトと骨を更新した。

- Tripo v3: `idle` / `walk` / `run`、`animate_in_place: true` を取得。リグ25＋モーション30＝55 credits。
- Meshy: Animation Library 678件を照会。既存採用候補225/227と待機・移動を比較。
  初版は同梱済み `Archery Shot 1`（225）を補正し、primeとの比較基準にした。
- Meshy prime: プラン更新後に3秒・1案の弓攻撃を生成、10 credits。
  52骨のFBXを保存して既存リグへ変換。体幹と腕のひねりを採用し、手足は接触制約で補正した。
  元の指は静止し、右腕が顔を横切るため、生の動作をそのまま使わず握り・離弦・狙いを仕上げた。
  最初のHTTP 402ではタスク作成・課金なし。更新後の成功タスクは1件のみ。

タスクID、費用、公式仕様リンクは [API記録](MOTION_H025_API.json)。
原本GLB、API状態、変換レポートは `build/h025-motion/` に保存。キー・署名URLはコミットしない。
prime原本は同ディレクトリの `moon_archer_attack_prime.fbx`。
中断後は `tools/h025_motion_api.mjs` の状態記録を引き継ぐ。状態を消して有料コマンドを繰り返さない。

## 初版の仕上げとゲーム再生（10月23日の変更前）

`H025MotionClips.json` に待機3秒、歩行1.1秒、走行0.8秒、攻撃1.5秒を収録。
Tripo素材の体幹・四肢の回転を使い、H025の実際の腕・脚の長さで接地と握りを補正した。
歩行・走行の支持脚は移動速度を打ち消す足運びにし、水平ルート移動を無効化。
接地中の足首、離地時のつま先、弓を保つ左手、右手の引き・指の開きを調整した。
攻撃は構え→引き絞り→狙い→25フレーム目の発射→45フレーム目の復帰。
primeの狙い待ちを短縮し、元66フレーム目のフォロースルーを発射に合わせた。
開始・終了を同じ待機姿勢へ合わせ、速度に応じた歩行／走行と状態間クロスフェードを使う。

既存15区間は変更せず、必要な肩2・つま先2・指30だけを `detailJoints` / `detailRot` で追加。
追加回転は実際のUSD関節軸でのローカル・レスト後差分（`restLocal⁻¹ * animatedLocal`）。
手首・足首は既存区間を利用する。H025の追加クリップだけを参加時に読み込む。
弦はロード中に作る2本の棒を再利用し、右指の接点から発射時に戻る。
発射イベントは既存シミュレーションの `attackReleased` を使用し、移動・攻撃判定は変更しない。
高速連射では復帰時間とクロスフェードを短縮する。移動攻撃では下半身の歩行を維持する。

## 再現と確認

`VELSTRIA/` を作業ディレクトリとして実行する。

```sh
blender -b -P tools/blender/author_h025_motion.py
blender -b -P tools/blender/preview_h025_motion.py -- --video
```

取得済み素材の15区間は `tools/motion/h025-source-clips.json` に保持。
primeは `tools/motion/h025-prime-source-clips.json` と補助関節の `h025-prime-source-details.json`。
`extract_h025_prime.py` がSMPL-Hの骨名・座標系を変換し、FBXの腰原点差を除去する。
原本から抽出し直す場合は `tools/motion/h025-source-spec.json` と既存 `extract_clips.py` を使用する。
`extract_h025_source_details.py` は取得素材で失われる34関節も別途検査・保存する。
元のrunには大きな継ぎ目があるため、仕上げでは終端の回転を補間して接地IKを適用する。

Windows / Blender 4.5.10 LTS のオフライン確認で、再ターゲット方向誤差は最大0.0102°。
primeの方向誤差は最大0.0093°。実ゲーム確認で見つかったルート骨への腰移動の二重適用を
Blender側で修正し、出力する腰移動をRealityKitと同じ1回の加算に合わせた。
仕上げのループ端および攻撃の始終姿勢は一致し、設定した手足ターゲットは到達可能。
Blender比較動画は完成済み23骨モデル＋旧クリップと、補修済み65骨モデル＋新クリップの姿勢比較。
変更前mainのゲーム画面を録画したものではない。弓メッシュはゲーム寸法に合わせた近似。
実際のRealityKit再生・シミュレーション発射は `H025 Motion Preview` Actionsの動画で別途確認する。
実機FPSの改善は主張しない。既存の三角形・Entity・演出予算を引き上げていない。

詳細な実機操作、急旋回・傾斜・通信遅延時の見た目の評価はコミュニティ側の確認対象。
