# 5v5 Canyon（2026-10-21）

ユーザー提供の `5v5-game-map.zip` を追加し、`MapDefinition.map(for:)` の通常・ランク・カスタム・練習・観戦用の既定マップを `canyon` に変更。乱闘とマジックチェスは従来どおり。以前のステージ定義 `relayout` は比較・回帰テスト用に維持する。

## 座標とゲーム判定

- 元の FBX の XY 平面を180度回転し、青を左下・赤を右上へ配置。一辺97.2m。元データの中心 `(12.6, 5)`、範囲336を同じ縮尺で描画・当たり判定へ変換する。
- 塔18基・コア2基は FBX 内の構造物の配置原点を使い、破壊できる既存のゲームエンティティで表示。FBX 内の静的な塔・コア・兵士・モンスターは描画データから除外する。
- 岩の投影形状を通行判定へ変換。外周の床の外は進入不可。草むらは元の12グループのメッシュを表示し、その投影形状から600×600格子の隠蔽判定を生成する。
- 北西の青い紋章の円形広場（約34.89m, 65.96m）と南東の紫の紋章の円形広場（約62.95m, 30.95m）をボス出現地点と判断。既存のタートル→8分からロード、撃破後に反対側へ移るルールを維持する。
- ジャングルのキャンプは各空き地に配置。壁とモンスター・紫バフの仔が重なる場合は、地形を削らず近傍の空き位置へ寄せる。

## 描画と予算

`StagePrep` が選択中のステージだけを背景準備する。元の繰り返しUVはタイル境界で三角形を分割してからアトラス化。材質・12m格子で結合し、プレイ中のメッシュ生成を行わない。

- `StageCanyon.bin`: 地形100,442三角形・210チャンク、元の草13,212三角形・12グループ（合計113,654三角形）。
- `StageCanyonAtlas0...2.png`: 各2048×1024。元の草も同じアトラスを共有し、グループ単位の半透明化を維持する。
- 葉はアルファカットアウトで深度を書き込み、透明カードの並べ替えを不要にする。地形の手描き陰影は unlit 材質で保持する。
- 低画質の既存60万三角形予算内。旧ステージの予算・テスト上限は変更しない。実機FPSの比較計測は行っていない。

## 再生成

```sh
uv run --with numpy --with pillow --with shapely --with scipy \
  python VELSTRIA/tools/stage/import_canyon.py /path/to/5v5-game-map.zip
bash VELSTRIA/tools/stage/build_shaders.sh
```

Blenderを `/Applications/Blender.app` から使用する。中間データは `VELSTRIA/build/stage/canyon`。元ZIPはリポジトリに含めず、SHA-256を `CanyonLayout.json` に記録する。

`CanyonMapTests` が全キャンプへの到達性、構造物・初期出撃位置、3レーンの通行とボスルールを確認。`StageTests.testCanyonStageFitsExistingBudgets` が読み込み・シーン構築・画質別予算、別テストが破損データと予算超過時の拒否を確認する。

検証環境: macOS上のSwift Packageテスト、新規マップ3件と乱闘8件が通過。iPhone 17 Proシミュレータ / iOS 26.3 / DebugでビルドおよびStageTestsの新規読み込み・破損データ・シェーダー更新・既存地形予算の4件が通過。実機の描画速度を保証する計測ではない。

実画面でunlit材質の出力を修正した後、シェーダーのハッシュ・関数存在テストも通過。同シミュレータの新規環境で約80秒の観戦を行い、新しい地形・テクスチャ・ユニット表示と試合進行を確認した。

## ジャギー・モアレ対策（2026-10-21）

- 床の負の高さを一律に切り上げて同じ平面へ重ねていた処理を廃止。地表付近の元の高さ差を保ち、深い岸だけを連続的に圧縮する。道路の縁の下地は16mm下げ、周囲の床との深度競合を避ける。元メッシュの重なる水平面の検査では、修正後に4mm未満で競合する組は0件（投影面積0.01m²超を対象）。
- アトラスの余白を4から16 texelに増やして画像とUVを再生成。明示的なミップマップ生成、異方性4、縮小時の小さなLODバイアスで、細かな石畳・葉のちらつきと隣のタイルの色漏れを抑える。
- 新ステージの中・高画質では既存の後処理合成に輪郭方向のアンチエイリアスを統合。平坦な領域はそのまま返し、追加の全画面パス・レンダーターゲットは作らない。低画質の後処理無効化は維持する。
- 三角形数100,442、チャンク数210、アトラス3枚のサイズ上限とゲーム判定データは変更なし。Pythonの高さ回帰テスト3件、Metalでの輪郭/平坦領域の画素テスト、後処理コンパイル、ステージの予算・シェーダー整合の5件を確認。実機の画質・速度の比較計測は未実施。シミュレータではRealityKitが後処理を呼ばないため、輪郭補正自体はMetalの画素テストで検証する。

## 元データの配置への整合（2026-10-21）

- タワーの非対称な外形の中心ではなく、FBXオブジェクトのワールド原点を採用。18基すべてを元データと照合（最大補正21.1cm）。コア2基にも同じ基準を適用し、レーン経由点を再生成した。レーン中央の大きな円形の床模様は元FBXでも塔の間にある装飾で、配置原点として扱わない。
- 草の外周を凸包で埋める近似と手続き生成の草を廃止。元の草メッシュ・UV・座標を保持し、同じ投影形状の凹みや隙間を隠蔽判定にも反映。通行不可の岩だけを判定から除外し、隠蔽面積は292.67m²から179.04m²になった。
- 草のIDを描画・隠蔽・半透明化で共用。既存3枚のアトラス内に収まり、草専用テクスチャとLODメッシュの追加ロードは不要。キャンプ・岩・川・泉の配置は変更なし。
- Pythonの配置・草の隙間・床面の回帰テスト5件、Coreのマップ検査3件、StageTestsの予算・描画と隠蔽の範囲・半透明化・破損拒否の2件を確認。元ZIPの中間データを使う照合でも全タワーとコアの原点一致を確認した。iPhone 17 Proシミュレータ / iOS 26.3 / Debugで約90秒の観戦を確認し、最新mainとの統合後もビルドが成功。実機FPSは未計測。
