# 5v5 マップ再配置（2026-10-15）

## 基準と今回の方針

提供された俯瞰画像の三レーン・対角の川・両端の拠点という構成を維持する。
既存配置はすでに参考画像の座標比を取り込んでいる（tools/map_proto/README.md）。
画像には距離目盛り・基準キャラ・移動時間がないため、MLBB の絶対寸法は確定できない。
MLBB 側の移動時間は未計測。本変更を「MLBB と同じサイズ」とは扱わない。

現状の移動処理を計測してから、比較用の暫定案として座標間隔を 1.10 倍にした。
意図は既存の壁・木・岩を大きくせず、レーン脇・ジャングルの通過余地を増やすこと。
1.10 は MLBB 実測から逆算した値ではなく、コミュニティで距離感を比較するための設計値。
MLBB 実測が得られた際は、同じ開始・終了地点で下表と比較して再調整する。

## 保存と変更範囲

- `MapDefinition.standard` は変更前の完全な配置として保存。
- 値コピーの `MapDefinition.relayout` 上で変更し、`map(for:)` から通常の試合に適用。乱闘は従来のまま。
- 座標・レーン制御点・泉・タワー・キャンプを 1.10 倍。壁は中心だけ移動し、矩形の縦横寸法・円の半径は維持。
- 草むらの領域・川幅は地形として拡張。個々のモデル、素材、キャラの寸法・移動速度・射程は変更しない。
- タワー・キャンプ・草むらの ID、順序、種類、所属、出現時刻を維持。外周の装飾は従来の個数・サイズで間隔だけ変更。
- 地面の配合マップは外周まで覆う範囲に拡張し、Metal シェーダーの同じ座標対応で再コンパイル。
- 地面、水面、霧、カメラ、観戦操作は使用中のマップ寸法を参照。ミニマップは既存の `ctx.map.size` 参照を継続。
- 経路探索・ミニオン・出現位置は同じ MapDefinition から生成。構造物・モンスターの向きも新しい中心を参照。
- リプレイ入力の地形条件が変わるため simVersion は 19 → 20（既存のバージョン不一致検査を適用）。

## 移動時間（MLBB ではなく自作ゲームの移動処理で計測）

環境: Apple Silicon Mac / Swift Package の Debug テスト。
H025 の素の移動速度 **262 単位/秒**、半径55、30 tick/秒を両マップ・両陣営で固定。
NavGrid の経路を実際の `MovementSystem.advance` / `resolveMove` で走行し、到着 tick を測る。
装備・エンブレム・泉の加速・戦闘・他ユニットの妨害を含めない孤立条件。
実機プレイのストップウォッチ測定でも、距離÷速度だけの推定値でもない。

サイドの指定地点は top の角を斜めに切る区間の中点（川の中心線との交点）。

## カメラと確認

キャラ追従では内側の境界クランプを適用せず、通常の前方オフセットを0にする。
既存の追従ばねは維持し、停止時はキャラの足元が画面中央。マップの四隅でも外側の地面・森を映す。
自由カメラには使用中のマップ寸法による制限を残す。倍率・キャラ速度で広さを偽装しない。

Core の新旧配置・全キャンプの到達性・レーン通行・草むらと壁の重なりを検査。
既存の StageTests を新配置で実行し、描画予算の上限は変更しない。
見た目の最終判断と MLBB 実測による倍率確定はコミュニティ側の確認対象。
実機 FPS 改善を主張する変更ではない。

検証結果: Core の WorldMapTests / BrawlTests / MapRelayoutTests 計21件通過。
最終寸法を整数13,200に固定した後も MapRelayoutTests 2件通過（上表の時間は不変）。
iPhone 17 Pro / iOS 26.3 Simulator / Debug の SpectatorCameraTests 18件 + StageTests 11件が
約65.5秒で通過。全画質の既存三角形上限・壁からのはみ出し・草むらの範囲・シェーダー整合を検証した。
