# 戦闘カメラを MLBB に合わせる（推定と確認）

2026-10-17 のユーザーの決定: 実際のプレイ画面のカメラも MLBB に合わせる。演出の大きさでカメラの差を埋め合わせない。
マップの形・判定には触れない（`CameraRig` の定数だけ）。

## 元にした測定（MLBB の画面収録。iPhone 横 1108×512・30fps）

`tools/mlbb_video/measure.py camera` で、ヒーローの足元を中心とする同心の照準の円から地面への写像
`u = u0 + x/(1+qz)`、`v = v0 − c·z/(1+qz)`（x, z はヒーロー px）を当てはめた値（README の各動画の表）:

| 動画 | u0 | v0 | c | q（/px） | 縮尺 s |
|---|---|---|---|---|---|
| ティグラル（3 つの円） | 556.6 | 295.0 | 0.7096 | 7.6 × 10⁻⁴ | 62.3 px / 単位（床の歩き） |
| アルカード（3 つの円） | 556.7 | 294.6 | 0.7107 | 7.8 × 10⁻⁴ | 同じ |
| ほか（場面ごとに足元だけ当て直し） | 554〜559 | 292〜296 | 0.7107 固定 | 7.7 × 10⁻⁴ 固定 | 通常攻撃の射程の円 1.78 / 2.48 = 公式 1.8 / 2.5 の −1% |

縮尺は、移動速度と床の歩きのほかに、**寸法が既知の地面の目印**（公式の射程の通常攻撃の照準の円）で −1% 以内に合っている。
MLBB の距離 1 単位 = Velstria の 1 m（sim の 100 単位）とする（スキルの幾何は MLBB × 100 で入れてある）。

## 解き方（ピンホールのカメラ・主点は画面の中心と仮定）

画面の高さ H = 512、中心 cy = 256。ヒーローの足元は中心より Δv = v0 − cy ≈ 38.6 px 下。見下ろし角 θ（光軸）・焦点距離 f（px）とすると、
足元の近くの地面の写像は `q = cosθ / f`、`c = sinθ + Δv · q` になる。

- `sinθ = c − Δv·q = 0.7107 − 38.6 × 7.7e-4 = 0.681` → **θ ≈ 42.9°**
- `f = cosθ / q ≈ 951 px` → 縦の画角 `2·atan(256 / 951)` ≈ **30.1°**
- 足元の光軸方向の奥行き `d = f / s = 951 / 62.3 ≈ 15.3 m`
- 足元が中心より下に映る = 注視点が足元より前（北）にある。前へのずれ F: `F·sinθ / d = Δv / f` → **F ≈ 0.91 m**、
  注視点までの距離 `D = d + F·cosθ` ≈ **15.9 m**

| | 見下ろし角 | 縦の画角 | 距離（zoom 1） | 注視点の前ずれ |
|---|---|---|---|---|
| 従来（legacy） | 56° | 48° | 10 m | 0 |
| MLBB の候補（mlbb） | 42.9° | 30.1° | 15.9 m | 0.91 m |

幅: 当てはめの幅（c 0.7096〜0.7107、q 7.6〜7.8 × 10⁻⁴、s ±1%）で θ は約 ±0.2°、画角は約 ±0.4°、距離は約 ±2%。
主点が中心という仮定・レンズの歪み無し・端末の縦横比（MLBB が縦の画角を保つか横を保つか）は確かめていない（推定）。

## 確かめ方

`-cameraPreset legacy|mlbb` で同じビルドの中で切り替える（`CameraRig.preset`。Debug の起動引数だけ。出荷ビルドは既定の組）。
比較撮影（`-fxCapture ... -fxCaptureRings`）は、ヒーローの足元に半径 3 m・6 m の水色の輪を置いた画と置かない画を撮る。
画の輪を `measure.py` と同じ写像で当てはめ、c・q・s が MLBB の値に合うかを見る（[README](README.md) の記録）。
