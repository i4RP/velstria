# 参照画像の体力ゲージ・中立モンスター寸法（2026-10-20）

`resource_compressed.zip` の26枚を、同じカメラで撮った実画面と重ね合わせた。
前回の地形合わせ後に大きく残っていたHPバーと、モンスターの体格を補正する。

## 通常プレイに反映した変更

- ヒーローHPの色面を1368×630換算で約104×9pxに設定。以前は幅約190px。
  自分・味方・敵に同じ寸法を使い、レベル章・名前・リソースバーも同じ基準で縮小する。
  章を含む横位置と頭上の高さも調整した。
- 距離補正をカメラとの直線距離から光軸方向の深度に変更。
  同じ奥行きでも左右端のバーが大きくなる問題を解消する。
- 中立のHP色面は通常約99px、バフ持ち約121px、ボス約170px。
  参照で読める通常・バフ・ボスの幅に分け、色は赤にした。
- 既存の生成モデルを種類ごとに調整。倍率はモデルのローカルX/Y/Z。
  メッシュ・骨・テクスチャ・同時表示数は増やさない。

| 種類 | X / Y / Z 倍率 |
| --- | --- |
| 蒼晶の番人 | 1.58 / 1.45 / 1.58 |
| 紅焔の番人 | 1.65 / 1.65 / 1.65 |
| 蒼晶の仔 | 1.45 / 1.15 / 1.45 |
| 棘角トカゲ | 1.10 / 2.00 / 1.10 |
| 熔岩の岩人 | 1.00 / 0.80 / 0.80 |
| 熾甲虫 | 0.62 / 0.53 / 0.62 |
| 宝殻蟹（成体） | 0.80 / 0.80 / 0.80 |
| 苔甲の徘徊者 | 0.80 / 1.00 / 0.80 |
| 古環の巨像 | 1.55 / 1.00 / 1.00 |

HP・状態表示の高さと接地影も調整。羽・尾・武器の先端をHPの高さにせず、頭や胴の上に置く。
被弾時の拡縮でも縦横比を保つ。当たり判定・射程・移動・出現時刻・マップ配置は変更しない。
画面外の詳細更新の間引きと既存のプール・描画予算を維持する。

## 比較資料と再撮影

ローカル資料（画像はgit管理外）:

- `build/stage/unit-scale-20261020/review/index.html`: 全26枚の全画面・50%重ね合わせ・差分。
- `build/stage/unit-scale-20261020/units/index.html`: モンスター拡大比較、自分・味方・敵のバー比較、HP実測値。
- `build/stage/unit-scale-20261020/units/measurements.json`: 1368×630換算のHP色面の幅・厚み・矩形。

```sh
uv run --with pillow python tools/stage/field_shots.py "$REVIEW_DEVICE" "$REVIEW_APP" \
  --unit-reference --out build/stage/unit-scale-20261020/captures
uv run --with pillow python tools/stage/compare_field.py build/stage/unit-scale-20261020
uv run --with pillow python tools/stage/compare_units.py build/stage/unit-scale-20261020
```

`compare_field.py` は比較ディレクトリ直下の `resource_compressed/` に元のJPEGを置いて実行する。
`compare_units.py` は前回の `build/stage/reference-20261019/IMG_*.png` を参照する。
シミュレータのPNGには画面方向のEXIFがないため、固定カメラの自分のHP位置から全体の回転方向を判別する。
画像の局所変形や、モデルだけの拡縮はしていない。

参照の敵は戦闘中・徘徊中・成体など状態が違う。`-stageUnits` では
`tools/stage/unit_reference.json` の種類・位置・向きだけを描画用コピーに適用する。
元のシミュレーションは動かさず、モデル・バーの寸法は出荷版と同じ経路で描く。
比較しやすい満タンのHPを表示し、実際のHP残量や名前を参照画像に偽装しない。

## 検証範囲

iPhoneシミュレータ（iPhone18,1 / iOS26.3）、Debug、highで撮影。
自分のHP幅は26枚で103〜106px、中央値104px。味方・敵は各105px。
色のしきい値で数えた厚みは概ね8px（アンチエイリアスの境界を含む設計値は約9px）。
実機FPSの改善を示す計測ではない。

Debugビルド成功。`RenderLogicTests` のバー倍率・画面端の投影寸法・目盛り上限・
画面外更新・CreatureKey、`RenderSceneTests` のバー値反映・クリーチャープール、
`CreatureAssetsTests` の全種類の読み込みと動作区間の計8件が成功した。
全26枚と敵味方比較の撮影中にクラッシュは発生しなかった。

元画像とはモデル固有の形状・武器・翼の曲がり方・動作が異なるため、輪郭全体のピクセル一致には至っていない。
特に番人の翼、岩人の腕、トカゲの頭飾り、巨像の武器と水の胴体に差が残る。
比較資料はそれらも隠さず表示する。今回はHP寸法と種類ごとの体格の補正を扱う。
