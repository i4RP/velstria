# エンブレム（MLBB のエンブレムを写したもの。旧「ルーン」の置き換え）

2026-10-14 に、仮置きだった「ルーン」（5 パス × 3 Tier の 30 個・割合の効果）を廃止し、Mobile Legends（MLBB）の
「エンブレム」をそのまま写した。7 つのセット（能力値 3 つ）と、3 段の天賦（通常天賦 8 個 / 8 個 + コア天賦 10 個）。
天賦は「組み換え自由」で、どのセットにもどの天賦でも付けられる（各段の天賦はその段のものだけ）。

出典（数値・文言の正はこの順）:

1. MLBB 日本語クライアントのスクショ（ユーザー提供。公開リポジトリには入れない）
   - 最大レベルのアカウント: 通常共通エンブレム Lv60・オーダーエンブレム(タンク) Lv60 のエンブレム画面、天賦のピッカー 3 段
     （1 段目で 活力、2 段目で 強靭、コアで 弱点分析 を開いたもの）、一括設定、ハンターの 🔍（エンブレムステータス）
   - フレンドの低レベルのアカウント: アサシン Lv26・サポート Lv29 のエンブレム画面、タンク Lv28・通常共通 Lv42 の 🔍
   - 用語説明（ステータス説明）: 能力値の名前（通常攻撃吸収・スキル吸収・混合吸収・物理貫通・魔法貫通・回復効果 など）
2. MLBB Fandom の [Emblems](https://mobile-legends.fandom.com/wiki/Emblems)（2026-04 更新、1.9.64 を含む）。Lv60 の数値と天賦の英文

### 誰がどのエンブレムを使うか

- **人間**: 一括設定で付けたもの（`Profile.heroEmblems`）。無ければ選んだバトルプラン（未設定は「有効」のプラン）のエンブレム、
  プランの無いヒーローはロール別の既定。レベルはプレイヤーのそのセットのレベル（新規は Lv1 から。能力値はそのレベルの値、天賦は解放レベル以上の段だけ）。
  そのセットを解放していなければ通常共通。`EmblemMath.loadout`。
  `MatchFactory.*Match(humanEmblem:)` に nil を渡すと、ファクトリーが選んだプランのエンブレム（Lv60）を付ける。
- **ボット**: 「有効」のバトルプランのエンブレム（H025〜H034。下の表の **有効** の行）。プランの無いヒーロー（H001〜H024）はロール別の既定。
  常に Lv60・全セット解放済み。`EmblemCatalog.botLoadout`。ランク戦のドラフトで AI のヒーローを差し替えた時も付け直す（`DraftEngine.apply`）。
- **ロール別の既定**（`EmblemCatalog.roleDefault`。セットの既定の天賦 = MLBB の既定）:
  ヴァンガード = タンク（活力 / 強靭 / 強震撃）、デュエリスト = ファイター（堅固 / 血の祭典 / 勇猛の一撃）、
  アサシン = アサシン（破砕 / 暗殺の達人 / 殺戮の連鎖）、アルカニスト = メイジ（啓発 / 掘り出し上手 / 致死の発火）、
  レンジャー = ハンター（致命 / 武器マスター / 弱点分析）、サポート = サポート（敏捷 / 立て直し / 集中マーク）。
- テストなどで `PlayerSlot` を直接作るとエンブレムは無い（`emblem: nil`）。キットのバランス計測（`KitBalanceTests` の `SkillWorld.addHero`）も
  両者エンブレム無しなので、キットのヒーローと汎用ヒーローの比べ方は変わらない。

### 適応（適応攻撃・適応貫通・適応ダメージ）

日本語クライアントの用語説明（共通用語）:

> **適応攻撃**: 追加物理攻撃が追加魔法攻撃より高い場合、物理攻撃がこのステータス値の分だけ上昇する。追加魔法攻撃の方が高い場合は、
> 魔法攻撃が同じ値だけ上昇する。2つのステータスが同じ場合は、ヒーローのダメージタイプによって決まる。
> **適応貫通**: 同上の判定で、物理貫通 / 魔法貫通が上昇する。**適応ダメージ**: 同上の判定で、物理ダメージ / 魔法ダメージになる。
> **混合回復**: HP+MP回復。**混合防御**: 物理+魔法防御。**混合防御貫通**: 物理+魔法貫通。**混合吸収**: 通常攻撃吸収+ スキル吸収。

- 比べるのは **追加** の物理攻撃と魔法攻撃だけ（レベル成長の素の値は除く。合計で比べると、魔法のヒーローも素の物理攻撃のせいで物理になってしまう）。
  同じ（序盤の 0 同士を含む）ならヒーローのダメージタイプ（マスターのスキルの種類）。
- 能力値（`ItemStats.apply`）: 追加の量は装備とエンブレムの固定の物理攻撃・魔法攻撃（メイジのセットの魔法攻撃 30）。装備の適応攻撃も同じ判定にまとめた。
- 天賦の適応ダメージ（不純な怒り・致死の発火）: `ItemEffects.adaptiveIsMagic`（その時の能力値の追加分。状態効果の強化も含む）。
- 🔍 の画面は、能力値の下にこの用語説明を出す（`EmblemAttributeKind.glossaryJa`。用語説明に無い HP・移動速度・魔法攻撃・攻撃速度は出さない）。

  混合吸収 = 通常攻撃吸収 + スキル吸収、回復効果 = 与える回復・シールド（`Stats.healShieldPower`）。HP回復・MP回復は毎秒の量（装備と同じ）。

## 天賦

画面ではタレントを「天賦」と呼ぶ（🔍 では「通常天賦：<名前>」「コア天賦：<名前>」）。1 段目の天賦には橙の小見出しが無い（ピッカーの画面どおり）。
日本語名・説明は画面で確かめたものだけ「確定」。ほかは Fandom の英文からの仮の訳で、残りのスクショが届いたら差し替える
（`EmblemTalentDef.jaConfirmed` / `textConfirmed` / `subtitleConfirmed`）。

（`planwork/emblems/*.png`。一時フォルダ）と画素の差で照合し、見比べ用のシートで目で確かめた。

  Fandom の画像名が `Weapon Master (Talent).png` で、前回の取得（`Weapons Master`）では見つからなかった。取り直した画像と一致し、
  ピッカーの 2 段目の 8 番目（Fandom の一覧の 8 番目）でもある。ハンターの 🔍 で名前も確定した。

## 解放・レベル・入手（仮の数値で実装済み。2026-10-14）

MLBB では、新規プレイヤーは通常共通エンブレムだけを持ち、ほかの 6 つはマジックダストで解放する。セットごとにレベル（1〜60）があり、
そのセット専用の欠片（エンブレムの欠片）とマジックダストで上げる。能力値はレベルで伸び、天賦もレベルで解放される。
これを **仮の数値** で実装した（ユーザーの指示「詳しくはいま写真撮れないから調べるか、適当に作って」）。
画面で確かめた点と第三者の攻略の値に合わせ、分からないところは決めた値。数値はすべて 1 か所の表にある:

| 何を | どこ | 値（仮） |
|---|---|---|
| 強化の費用・キーレベル・天賦の解放レベル・能力値の表 | `Packages/VelstriaCore/Sources/VelstriaCore/Data/EmblemProgression.swift`（`EmblemProgression`） | 下の表 |
| 解放の費用・入手の量・宝箱の時計・1 週間の見込み | 同じファイルの `EmblemEconomy` | 下の表 |
| プロフィールの操作（解放・強化・欠片・宝箱） | `App/Services/EmblemService.swift` | |
| 保存 | `Profile.magicDust`（マジックダスト）・`emblemFragments`（セット ID → 欠片。通常共通は無し）・`emblemSetProgress`（解放・レベル）・`emblemChest`（宝箱）・`emblemGrandfathered`（旧版から引き継いだプレイヤー） | |
| メールの添付 | `MailAttachment.Kind.magicDust` / `.emblemFragment`（`refID` = セット ID）。旧版の種類はそのまま読める | |

### 規則

- **新規**: 通常共通エンブレムだけ解放済みの Lv1。ほかの 6 つは未解放（Lv1）。ウェルカムメールにマジックダスト 500（セットを 1 つ解放できる量）。
- **解放**: マジックダスト **500**（`EmblemEconomy.unlockCost`。MLBB の費用は不明）。解放したセットは Lv1 から。
- **強化（アップグレード）**: そのセットの欠片を先に使い、足りない分をマジックダストで払う（1:1。画面の「10+217/227」= 欠片 10 + マジックダスト 217 / 必要 227）。
  通常共通は欠片が無くマジックダストだけ（「217/227」）。最大（Lv60）は「MAX」で強化できない。旧来の BP（Coin）の費用は使わない。
- **欠片の繰り越し**: 最大レベルのセットの欠片は、受け取った時と最大になった時にマジックダストに 1:1 で替える（通常共通の欠片もマジックダスト）。
  未解放のセットの欠片は貯められる。
- **天賦の解放**: 1 段目 **Lv10**・2 段目 **Lv15**・コア **Lv20**（`EmblemProgression.talentUnlockLevels`。仮）。解放レベル未満の段は画面で鍵と
  「Lv○で解放」を出し、付け替えられず、試合でも働かない（`EmblemLoadout.activeTier1` / `activeTier2` / `activeCore`）。付け替えに費用は無い。
  MLBB の「期間限定で全天賦解放」は `EmblemProgression.allTalentsUnlocked`（今は false）。天賦ごとの解放レベル（`EmblemTalentDef.unlockLevel`）は
  不明なので全部 nil（段の解放レベルを使う）。
- **試合**: 人間の能力値はプレイヤーのそのセットのレベルの値（`EmblemLoadout.level`。`EmblemMath.loadout` が付ける）。一括設定で付けた 1 式も
  今のレベルで使う。**ボットは常に Lv60**。古い試合構成・リプレイ・オンラインのロードアウトでレベルが無ければ 60。
  能力値と天賦の働き方が変わるので `MatchConfig.currentSimVersion` を 18 に上げた。
- **旧版のプレイヤー**: `Profile.schemaVersion` を 4 に上げ、3 以前の保存は `ProfileMigrator` が 7 つのセットを解放済みのまま今のレベル
  （保存が無ければ 60。f8d65cd では全員 60）で書き込み、`emblemGrandfathered` を立てる（テスターが今の強さを失わない）。新しく入れた人は新規の状態から。
  デバッグの `-grant` も同じ（全セット Lv60）。`-emblemFresh` は新規の状態（マジックダスト 2,000・アサシンの欠片 10・宝箱 1 回分）で解放・強化を試せる。

### 入手（決まった量。`EmblemEconomy`）

MLBB の入手（4 時間ごとの無料の宝箱・デイリー / ウィークリーの宝箱・ミッション・実績・週の幸運の宝箱・エンブレムマトリックス・スターライト）のうち、
今のゲームにある仕組みに載せた。**有料のガチャ・有料の通貨で引く確率の入手は作らない**（確率の表示などの法令の要件）。どれも決まった量。

### 1 週間の見込み（`EmblemEconomy.weeklyIncome` / `weeksToMax`）

普通の遊び方 = 1 日 4 試合（勝率 5 割、12 分以上）・宝箱 1 日 3 回（朝・昼・夜）・デイリー / ウィークリーをすべて。デイリーの 3 枠目は 4 つから 1 つ
（D09 とロールの 3 つがそれぞれ 1/4）。

| 入手 | マジックダスト / 週 | 欠片 / 週 |
|---|---|---|
| 試合 | 7 × 4 × (0.5 × 15 + 0.5 × 8) = 322 | |
| 宝箱 | 21 × 15 = 315 | 21 × 10 = 210（6 セットに 35 ずつ） |
| デイリー | 7 × (30 + 20 + 1/4 × 20) = 385 | 7 × 1/4 × 15 = 26.25（タンク・ハンター・サポート） |
| ウィークリー | 120 + 80 + 80 = 280 | 6 セットに 15 ずつ |
| 合計 | **1,302** | 50（アサシン・メイジ・ファイター）/ 76.25（タンク・ハンター・サポート）/ 0（通常共通） |

- 1 つのセットに使える量 = マジックダスト + そのセットの欠片 = 1,302〜1,378 / 週。Lv1 → 60（22,773）に **16.5〜17.5 週 ≒ 3.8〜4.0 か月**
  （目標の 3〜5 か月の中）。解放の 500 はウェルカムメールの粉、スターパスの粉（900 / シーズン）は入れていない。
- 少なめ（1 日 2 試合・宝箱 2 回）は約 21 週（4.9 か月）、多め（1 日 8 試合・宝箱 4 回）は約 13 週（2.9 か月）。
- マジックダストは全セットで共有するので、2 つ目のセットは欠片の分だけ速くはならない（並べて上げると 2 倍かかる）。最大のセットの欠片は粉になるので無駄にならない。
- 量を変える時は `EmblemEconomy` の値を変え、`EmblemProgressionTests.testNormalPlayMaxesOneSetInThreeToFiveMonths` で 3〜5 か月に収まるかを確かめる。
